# Sandbox Stripe demo

`/takeout` is an invented venue's pickup demo, with a multi-item one-time cart and a separate fixed monthly pickup subscription. Nothing on the site takes payment or contact information, writes an order, sends mail, or activates fulfillment. A visit to the return URL is not proof of payment. Never use real information, real cards, live keys, or live Stripe objects.

## Layout (current architecture)

- The `/takeout` page, catalog (`demo-checkout-catalog.json`), nav link and checkout CSS are **rendered** by the pack compiler from the venue manifest's optional `checkout` section (`packs/hospitality/demo/venue.json`). Venues without a `checkout` section render nothing checkout-related at all; never hand-edit `core/public/*`.
- The `POST /api/checkout` route lives in `crates/sws-worker-site` (`src/checkout.rs` holds the host-testable policy; the wasm glue wires Turnstile, the sandbox Stripe API, and the assets binding). It records no orders, handles no webhooks, and does not fulfill anything.

## Setup (remote steps require explicit approval)

1. In a **Stripe sandbox**, create fixed USD Prices for the non-alcohol items in the demo manifest's `checkout` section. Use standard per-unit pricing with no quantity transform: three one-time Prices ($12.00 flatbread, $6.50 soup, $3.00 cookie), and one $16.00 recurring Price billed **every month**, licensed (not metered), for one bag of pickup beans. Use fictional product names, no shipping, no trial, and no fulfillment integrations. The manifest is the source of expected amounts; the compiler emits the page and a public, read-only catalog with item keys and cents, not Stripe configuration.
2. Use a sandbox restricted key with Prices read and Checkout Sessions write permissions (or a sandbox secret key if necessary). Put it only in the Worker secret `STRIPE_DEMO_SECRET_KEY`; accepted prefixes are `rk_test_` and `sk_test_`. Never paste it into logs, chat, an issue, a manifest, or a tracked file. Use Cloudflare's secret prompt or approved secret tooling, not a command-line argument.
3. Set non-secret Worker var `STRIPE_DEMO_PRICE_IDS` to a JSON object string mapping each manifest item ID, including the subscription, to its actual sandbox Price ID. Shape: `{"flatbread":"price_REPLACE","soup":"price_REPLACE","cookie":"price_REPLACE","beans":"price_REPLACE"}`. Set `DEMO_CHECKOUT_ORIGIN` to the public site's exact canonical HTTPS origin (no path). Use the same origin in the production asset render. These vars must be set on the deployed Worker environment, not another environment. A local loopback HTTP origin is supported for local testing.
4. Render assets with that hostname's **real public Turnstile site key** and provision the corresponding `TURNSTILE_SECRET_KEY` through the project's approved secret procedure. Only configure the demo hostname on the Turnstile widget. Checkout requires a successful Siteverify and, for a real widget, the expected hostname and `demo_checkout` action. Documented dummy secrets still go through Siteverify and are accepted only when the actual request origin exactly matches the configured loopback origin. `DEV_MODE` cannot bypass checkout verification.
5. Deploy Worker and generated assets together only after approval. Existing `_headers` and `/js/forms.js` are still emitted by the compiler; the checkout catalog and page come from the pack-rendered bundle. Checkout is unavailable without configuration. Don't add webhooks, a database, or automatic order processing for this demo.

The subscription uses its own server-created hosted Checkout Session rather than a Payment Link: the Worker can enforce the sandbox Price, quantity, cadence, currency, total and returned session/URL before handoff. Changing prices requires regenerating the static assets and updating the Stripe Price mapping together. Card is the only payment method requested; adaptive pricing and automatic tax are disabled. CSP permits native form redirects to the exact hosted Checkout origin, not Stripe JS, frames, or browser API calls.

## Local checks and approved smoke tests

- Locally use the repository's unit/mocked Stripe tests, Playwright and Lighthouse. No local Stripe key is needed for those checks. Browser tests block third-party requests and simulate the widget when testing the native form navigation. The site enhancement script only updates the total; with it blocked, native form POST still works **if Turnstile's browser JavaScript remains enabled**. With all JS disabled, checkout deliberately can't pass Turnstile.
- Only after approval, verify the sandbox dashboard is active and environment variables target the sandbox. Visit the public page, confirm no Stripe request on load, then submit a cart with two different items and confirm the hosted `checkout.stripe.com` page shows the exact USD total and sandbox mode. Repeat with the subscription and confirm one item billed monthly. Test cancel and success returns; these pages never claim fulfillment. For a sandbox-only confirmation use Stripe's test card `4242 4242 4242 4242`, any future expiry, any three-digit CVC and fictional details (e.g. `pickup@example.com`). Confirm only sandbox objects were created; cancel the test subscription in the sandbox when done. Do not log full session links or tokens. Verify parity on static, error, and 303 responses; don't record redirect locations in shared logs.
