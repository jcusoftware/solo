Accessibility & Security

Accessibility and edge security are first-class compiler and CI gates in Solo Website System — not optional plugins bolted on after launch.

WCAG 2.2 Level AA (Native Semantics Only)

  • Heading structure: Exactly one <h1> per page, starting the outline, with sequential heading levels and no skipped levels.
  • Landmarks & navigation: Every page includes <html lang="...">, <header>, <nav>, <main id="main" tabindex="-1">, <footer>, and a keyboard-visible skip link.
  • Color contrast: Minimum 4.5:1 for normal text and 3:1 for large text and UI components.
  • Focus & targets: Unobscured :focus-visible outlines and interactive targets at least 24×24 CSS pixels.
  • Forms: Explicit <label> associations, aria-describedby validation messages, aria-live status announcements, and full no-JS fallback.
  • Zero overlay widgets: Third-party accessibility overlays are explicitly banned and detected by automated Playwright checks.

Dual Security-Header Contract

Cloudflare's _headers file applies only to static assets. Every dynamic /api/* response handled by the Rust edge Worker must apply the exact same header set via with_security_headers.

Header Enforced Value
Strict-Transport-Security max-age=63072000; includeSubDomains; preload
X-Content-Type-Options nosniff
X-Frame-Options DENY
Referrer-Policy strict-origin-when-cross-origin
Permissions-Policy Disables accelerometer, camera, geolocation, gyroscope, magnetometer, microphone, payment, usb, browsing-topics
Cross-Origin-Opener-Policy same-origin
Content-Security-Policy default-src 'self', Turnstile allowlisted on https://challenges.cloudflare.com, style-src 'self', object-src 'none', frame-ancestors 'none', upgrade-insecure-requests

Four independent checks enforce header parity: Rust unit tests (cargo test), static Node parity (npm run check:headers), live parity (npm run check:headers:live), and Playwright E2E (tests/headers.spec.mjs).

Edge Worker & Data Safety

  • Request body limits: Streaming body reads capped at 16 KB to protect Worker memory and stay far under the 128 MB isolate limit.
  • Bound D1 SQL parameters: Every Cloudflare D1 query uses bound parameters; user input is never interpolated into SQL strings.
  • No panics on untrusted input: Worker handlers avoid unwrap() on request payloads and return structured JSON error responses.
  • Cloudflare Turnstile: Required on public form endpoints. Production secrets live strictly in Cloudflare Worker secrets (wrangler secret put) and never in Git.
  • Wasm-safe Rust dependencies: No native OpenSSL, C-assembly ring, OS threads, tokio, or blocking filesystem I/O in Wasm crates.

Reporting Security Issues

Please report potential security vulnerabilities privately according to SECURITY.md in the repository rather than opening a public GitHub issue.
