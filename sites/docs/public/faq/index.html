FAQ & Troubleshooting

Common questions about Solo Website System and quick fixes for local development, CI, and deployment issues.

Frequently Asked Questions

Why build a website builder in Rust for Cloudflare Workers?

Compiling site IR in Rust produces deterministic, sub-millisecond static builds, allows the same compiler crates (sws-ir, sws-css, sws-compiler) to run natively in the CLI and inside browsers via WebAssembly, and compiles edge form handlers to tiny, memory-safe wasm32 Cloudflare Workers.

How much does hosting an SWS site cost?

Small and medium sites run for $0/month on Cloudflare's free tier (Workers Static Assets, 100k Worker requests/day, 5 GB D1 SQLite, Turnstile, and DNS). Paid Cloudflare Workers plans are only needed if your traffic or storage exceeds free-tier limits.

Can I use SWS without buying a custom domain yet?

Yes. Every Wrangler configuration enables workers_dev: true so sites deploy immediately to *.workers.dev. The SWS landing and docs configs bind solo.jcusoftware.com and docs.jcusoftware.com by default; for forks or preview environments without a custom domain, comment out the routes blocks in both wrangler.jsonc files and set SWS_LANDING_URL and SWS_DOCS_URL GitHub repository variables to your *.workers.dev URLs.

Why are accessibility overlay widgets banned?

Third-party overlay scripts do not repair broken native HTML semantics, often introduce keyboard or screen-reader conflicts, and expand your CSP attack surface. SWS enforces WCAG 2.2 Level AA natively in HTML/CSS and verifies it automatically with axe-core and Lighthouse.

Why aren't prebuilt CLI binaries attached to an early release tag?

The tag release workflow checks whether crates/sws-cli/Cargo.toml exists on that tag. Tags cut before sws-cli lands on main publish as verified source releases without broken download links; once sws-cli is present on a tagged commit, all five cross-compiled platform archives and SHA256SUMS.txt attach automatically.

Troubleshooting

worker-build not found during npm run dev or npm run build

Install worker-build and make sure Cargo's bin directory is in your shell PATH:

cargo install worker-build@^0.9 --locked
export PATH="$HOME/.cargo/bin:$PATH"
which worker-build

POST /api/newsletter or /api/inquire returns HTTP 503 locally

The Worker refuses to process public form submissions when TURNSTILE_SECRET_KEY is missing unless DEV_MODE="true" is set. Copy the example local vars file before running npm run dev:

cp .dev.vars.example .dev.vars

cargo deny check fails on a new Rust dependency

SWS enforces a strict permissive OSI license allowlist (MIT, Apache-2.0, BSD-2-Clause, BSD-3-Clause, ISC, Unicode-DFS-2016, CC0-1.0). Copyleft and source-available crates (including MPL-2.0 crates such as lightningcss or cssparser) are rejected intentionally. Replace the dependency with a permissively licensed alternative.

npm run check:headers or cargo test fails with a header mismatch

Any security-header update must be applied to crates/sws-security/src/headers.rs and core/public/_headers in the same commit, and static sites must be regenerated so sites/*/public/_headers stay synchronized:

npm run sites:build
npm run check:headers
npm run sites:check:headers
cargo test --workspace

npm run render:check or npm run sites:check reports drift in CI

Source data or templates changed without regenerating the committed static output. Regenerate locally and commit the updated files:

npm run render
npm run sites:build
npm run verify

Playwright fails because Chromium is missing

npx playwright install --with-deps chromium

Still stuck?

Open a bug report or question on GitHub Issues with your OS, Rust/Node versions, and the exact command output.
