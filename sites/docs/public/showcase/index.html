Live Showcase: shirlington-hearth-demo

SWS ships a complete, 100% fictional reference showcase demonstrating the core Rust edge Worker, deterministic static HTML/CSS compilation, and the hospitality vertical pack.

Local & Deployable Demo Live showcase URL not yet configured

You can run the full interactive shirlington-hearth-demo showcase locally in under two minutes using the commands below, or set the SWS_SHOWCASE_URL repository variable once a public showcase Worker is deployed so this page links directly to it.

Why the Showcase Is 100% Fictional

Public open-source fixtures in SWS strictly follow a two-zone IP and trademark firewall. shirlington-hearth-demo uses invented street addresses (Hearthstone Lane), RFC-style 555-01xx phone numbers, and .example domains so zero real third-party business names, logos, menus, or trademarks appear in the public repository.

What to Inspect in the Showcase

WCAG 2.2 AA & AAA Contrast

The demo palette delivers 13.97:1 body text contrast (exceeding WCAG AAA), a single <h1>, sequential headings, keyboard-reachable skip links, and zero accessibility overlay widgets.

Semantic HTML Menus & JSON-LD

Menu items render as real semantic HTML paired with Menu, MenuSection, and MenuItem structured data — never trapped inside an inaccessible PDF.

Progressive-Enhancement Forms

Newsletter and inquiry forms include explicit <label> bindings, aria-describedby errors, an unchecked CAN-SPAM consent box, and full server-side D1 persistence.

Live Dual Security Headers

Compare HTTP response headers on / (Cloudflare Static Assets via _headers) and /api/health (Rust Worker via with_security_headers) — they are byte-identical.

Run the Showcase Locally

git clone https://github.com/jcusoftware/solo.git
cd solo
npm ci
cp .dev.vars.example .dev.vars
npm run db:migrate:local
npm run render
npm run dev

Then open http://127.0.0.1:8787 and run the live verification checks in another terminal:

npm run check:headers:live
BASE_URL=http://127.0.0.1:8787 npm run test:a11y
npm run lhci
